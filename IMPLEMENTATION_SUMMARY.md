### ✅ Data Parsers

**SAP Parser (sap_parser.py)**
- Detects German headers (MATNR, WERKS, Menge, MEINS)
- Normalizes units:
  - Fuel: L, liter, m³ (CBM), kg, tonnes
  - Energy: kWh, MWh, Wh
- Converts large units to base units (tonnes→kg*1000, MWh→kWh*1000)
- Duplicate detection
- Data quality flags

**Utility Parser (utility_parser.py)**
- Handles decimal separators (German format: 1.000,50)
- Meter ID, billing period, consumption tracking
- Deduplication by (meter_id, start_date, end_date)
- Billing period alignment checking
- Data quality flags

**Travel Parser (travel_parser.py)**
- Concur/Navan format support
- Multi-segment extraction (AIRFR, HOTEL, TAXIF, RAILF, CARHIRE)
- Cabin class and distance tracking
- Round-trip handling
- Data quality flags

## Data Flow

### Upload Workflow
1. User selects organization and data source
2. Uploads CSV/JSON file via form
3. Backend receives file at `/api/raw-ingestions/upload/`
4. Parser extracts data based on source type
5. RawIngestion record created with parsed rows
6. NormalizedRow records created for each row
7. Data quality issues flagged automatically
8. Frontend refreshes to show new rows

### Approval Workflow
1. User views normalized rows in Review table
2. Clicks "Approve" or "Flag" button
3. Modal appears for confirmation/notes
4. User submits action
5. Row updated with approval status
6. ApprovalLog entry created for audit trail
7. Dashboard statistics updated

### Filtering/Sorting
- Frontend sends query parameters to backend
- Backend filters/sorts using Django ORM
- Pagination with 50 rows per page
- Results returned as paginated JSON

## API Documentation

### Response Format
All API responses follow standard format:
```json
{
  "count": 28,
  "next": null,
  "previous": null,
  "results": [...]
}
```

### Error Handling
- 400: Bad request (missing required fields)
- 404: Not found (organization/row not found)
- 500: Server error (parsing failure, DB error)

### Key Query Parameters
- `org_id` - Required for all endpoints (multi-tenant)
- `data_type` - Filter by SAP/UTILITY/TRAVEL
- `flagged` - true/false
- `approved` - true/false
- `start_date`, `end_date` - Date range
- `ordering` - Sort field (prefix with `-` for desc)

## Running the Application

### Backend
```bash

source venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
# API available at http://localhost:8000/api/
```

### Frontend
```bash
cd frontend
```

## Production Considerations

**Backend:**
- Use environment variables for SECRET_KEY, DEBUG, ALLOWED_HOSTS
- Use PostgreSQL instead of SQLite
- Set DEBUG=False
- Configure CSRF and CORS properly
- Use gunicorn/uWSGI for serving
- Set up proper logging
- Configure static file serving (CloudFront/S3)

**Frontend:**
- Run `npm run build` for production
- Deploy static files to CDN
- Configure API endpoint for production
- Set up error tracking (Sentry, etc.)
- Enable gzip compression
- Configure caching headers
